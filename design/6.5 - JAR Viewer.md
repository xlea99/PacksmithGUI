### 6.5 JAR Viewer

The JAR Viewer is a read-oriented archive browser for mod `.jar` files (and any other
zip-format archive Packsmith encounters). It solves a mundane but real pain: peeking
into a mod's internals currently requires an external tool that extracts files to a
scratch directory just to view them. The JAR Viewer lets the user do this in Packsmith
without leaving the workspace.

Its secondary, less mundane purpose is to provide a **save-as-override** workflow for
datapack and resource-pack files — the user opens a jar, edits a data or asset file in
place, and Packsmith writes the edited version into the user's datapack/resourcepack as
a proper override. The jar itself is never modified.

#### Workflow

1. User opens a jar — either by double-clicking it in the File Browser (§6.2), by a
   cross-reference from elsewhere, or by a dedicated "Open JAR..." action.
2. The JAR Viewer tab shows the jar's internal tree. The tree is read-only; the jar
   is never modified.
3. User double-clicks a file in the tree.
4. Packsmith extracts that file to a temporary directory and opens it in the appropriate
   editor — Text Editor (§6.3) for textual files, NBT Editor (§6.4) for binary NBT,
   hex/read-only view for anything else.
5. User reads, or edits.
6. On save (Ctrl+S), one of three paths fires depending on the file's internal path —
   see below.

The jar is never opened in read-write mode. The workflow is extract → edit copy →
write-somewhere-else. The original jar on disk is untouched.

#### Save-as-Override Targeting

The internal path of the extracted file determines what save does. There are exactly
three cases:

| Internal path                     | On save                                                    |
|-----------------------------------|------------------------------------------------------------|
| `data/<namespace>/**`             | Save-as-override prompt → datapack override                |
| `assets/<namespace>/**`           | Save-as-override prompt → resource pack override           |
| Anything else                     | Read-only, save disabled                                   |

The third case covers `META-INF/`, `mods.toml`, `fabric.mod.json`, `pack.mcmeta` at the
jar root, `.class` files, and everything that doesn't have a meaningful override target.
These files open **read-only** in the Text Editor (§6.3) — the user can view them but
the editor refuses edits and Ctrl+S is a no-op. See §6.3's read-only mode.

The first two cases **depend on the Global Pack Loader Integration (§7.1)** being set up
for the current profile. The loader integration provides:

- The user's datapack and resourcepack directories (Paxi, OpenLoader, Moonlight, etc.)
- The set of existing datapacks/resourcepacks to pick from
- Path computation from internal jar path → override target path

If no loader integration is active, the save-as-override prompt is replaced with a
read-only banner pointing the user at §7.1 to set one up. Foundational-but-optional:
without a loader mod installed, global overrides are not a thing Minecraft supports, so
Packsmith has nothing meaningful to do here.

#### The Save Prompt

When the user saves an editable override, a prompt appears with:

- **Target datapack / resource pack** — a picker of the user's existing packs, plus a
  "+ New Datapack" (or "+ New Resource Pack") option that triggers the same "new pack"
  flow the File Browser context menu uses.
- A preview of the override's resolved path — auto-computed from the internal jar path
  and the chosen target. The user doesn't have to think about namespace routing; they
  just pick the target.
- Confirm.

On confirm, Packsmith writes the edited content into the target pack at the resolved
path as a new user-owned file (§6.1). The temp-dir extraction is discarded.

#### Live Questions

##### Binary Preview Scope

For non-text, non-NBT files inside a jar (`.class`, `.png`, `.ogg`, fonts, etc.), what
does double-clicking do? Options: open a hex dump in the Text Editor (read-only), open
a format-specific viewer for known formats (image preview, audio playback), or refuse
to open and show a "no preview available" placeholder. Needs a call — probably
image/audio previews are worth it, hex dump is a reasonable fallback for everything
else.
