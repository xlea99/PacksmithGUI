### 8.2 KubeJS

KubeJS is the most widely-used scripting framework in modded Minecraft. Pack devs use
it for recipe manipulation, tag modification, custom events, and essentially anything
that would otherwise require writing a real mod. Packsmith's KubeJS integration makes
the authoring experience of KubeJS scripts significantly better by layering
registry-backed intelligence over the generic Text Editor.

The integration activates when `kubejs` is present in the packdump mod list.

#### Registrations

**Smart folders** in the File Browser (§6.2), under a `📜 KubeJS` category:

- `Server Scripts` — `kubejs/server_scripts/`
- `Client Scripts` — `kubejs/client_scripts/`
- `Startup Scripts` — `kubejs/startup_scripts/`

Plus asset and data directories if the profile uses them (`kubejs/assets/`,
`kubejs/data/`). The smart folders make the "which scope am I writing in" question
answerable at a glance instead of requiring the user to mentally map directory paths
to script phases.

**Context-menu actions** on those smart folders:

- "New Server Script..." / "New Client Script..." / "New Startup Script..." — creates
  a `.js` file with a minimal scaffold (file header comment, common imports if any).

**Text Editor language services** (§6.3) on `.js` files under `kubejs/**`:

- **Registry-backed completion.** Typing inside strings passed to `Item.of(...)`,
  `Block.of(...)`, `Ingredient.of(...)`, etc., triggers autocomplete pulled from the
  packdump's Layer 1 data. ID `quark:rope` is suggested because the packdump knows it
  exists; Packsmith doesn't need ProbeJS because it already has the authoritative list.
- **Hover info** for registry IDs — hover over `"quark:rope"` to see the display name,
  source mod, and registry type.
- **Tag autocomplete** for tag-API calls (`.add()`, `.remove()` on Forge tags, the
  whole KubeJS tag surface) — same mechanism, same packdump data.
- **KubeJS globals** (`event`, `ItemStack`, `Ingredient`, `RecipeEventJS`, etc.) get
  type hints and snippets. The catalog of what to surface is KubeJS-version-specific
  and maintained in the integration.

**Bottom panel** — a dedicated "KubeJS Logs" tab for tailing the KubeJS log file
(`logs/kubejs/*.log`). Auto-refresh on file change, syntax highlighting for common
error patterns (recipe registration failures, unknown IDs, etc.).

#### Ownership

KubeJS scripts are unstructured text files — each action writes its own `.js` file and
conflicts are prevented by filename. Per-file ownership, not per-key. See §6.1's
unstructured formats table.

#### Runtime Data Access (Speculative)

Since Packsmith has the full profile database and KubeJS scripts run inside the game,
there's a potentially interesting integration where KubeJS scripts can query Packsmith's
Layer 2 data at game runtime — "is this item marked `remove` in the user's tags?" — to
drive behavior from Packsmith's single source of truth rather than from hardcoded
script lists.

This is speculative and not part of MVP. It would require a runtime API surface (HTTP
socket? file-watched manifest?) plus KubeJS-side helpers. Noted as a direction; not
committed.

#### Live Questions

##### KubeJS Version Coverage

KubeJS's API changes across major versions. The integration's completion catalog
and smart-folder set need to target specific versions — start with whatever version
the user's profile has and adapt. How to version-detect (packdump mod version string),
and how much of the catalog is shared across versions vs. per-version, needs a
sitdown once we're implementing it.
