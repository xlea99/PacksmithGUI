## 9. Data Storage Design Principles

The packdump is **read-only, always.** It never gets modified by Packsmith. Anything the
user creates, decides, or configures **as data** lives in the SQLite database. The packdump
is truth from the game; the database is truth from the user.

The "as data" is load-bearing, and this section originally omitted it. Tags, blueprints,
views and jobs are data — structured, queryable, owned. **Code is not**: an authored action
is a Starlark source file in a package folder on disk (§3.3.1), not a row. §3.3.3's
`packages` and `actions` tables were specified and deliberately never built, because a
source file belongs somewhere you can edit it, diff it, and put it in version control —
not in a BLOB that has to be kept in sync with the file it was copied from.

Files the user edits (§6) are a third case again: they live where the game expects them,
and the database holds only Packsmith's *claim* on them (`file_ownership`), never their
contents.
